# Monorepo: apps/web, apps/landing-page, packages/ui

Branch `mika/landing-page` (PR #11). Worktree `.worktrees/landing-page`.

## Goal

Split the repo into two Next.js apps, following the layout of `~/repos/adeli`:

| Path | Package | What | Port |
| --- | --- | --- | --- |
| `apps/web` | `@adeli-chat/web` | The chat app (everything in `src/` today, minus the landing page) | 3030 |
| `apps/landing-page` | `@adeli-chat/landing-page` | The marketing page from PR #11 | 3031 |
| `packages/ui` | `@adeli-chat/ui` | Shared design system and the phone preview | n/a |

Root `package.json` workspaces: `["apps/*", "packages/*"]`. `packages/ui` is added because the landing page
reuses the web app's tokens, ui components, brand marks, theme toggle and `PhonePreview` (decided with the user).

Deploys are two Vercel projects on separate domains: the landing page at the root domain
(`<domain>.com`) and the app at `app.<domain>.com`. The domain is not chosen yet.

`apps/web/.env.local` is the only env file anyone needs. The landing page needs no env file.

## Decisions

1. **Yarn 4 workspaces, replacing npm**, set up like `~/repos/adeli`:
   - Root `package.json`: `"packageManager": "yarn@4.12.0"`, `"workspaces": ["apps/*", "packages/*"]`.
   - `.yarnrc.yml`: `nodeLinker: node-modules` (no PnP; Next, drizzle-kit and PGlite expect a real `node_modules`)
     and `yarnPath: .yarn/releases/yarn-4.12.0.cjs`, created with `corepack enable && yarn set version 4.12.0`.
     Commit `.yarn/releases/`.
   - `.gitignore`: add `.yarn/*` with `!.yarn/patches`, `!.yarn/plugins`, `!.yarn/releases`, `!.yarn/versions`,
     and `yarn-debug.log*`, `yarn-error.log*`.
   - Delete `package-lock.json`; one root `yarn.lock`. Keep the same dependency ranges so the resolved versions
     barely move; diff `yarn why next react drizzle-orm better-auth` against the old lockfile.
   - Sibling deps use `"@adeli-chat/ui": "workspace:*"`.
   - Root scripts: `yarn workspace @adeli-chat/web dev` for one app, and for all of them
     `yarn workspaces foreach -Apt --exclude adeli-chat run <script>` (the root is excluded, or root `test` calls
     itself; `-p` parallel, `-t` dependency order).
   - Every `npm run` in scripts, docs, CI and `.claude/launch.json` becomes `yarn`. `vercel-build` becomes
     `yarn db:migrate && next build`.
2. **No `LANDING_PAGE` flag.** The app's `/` always goes to `/automations` (back to pre-#11 behavior). Self-hosters deploy
   only `apps/web`; the landing page is our own site. Delete `src/lib/landing.ts`, the `/` and `landing/` exceptions in
   `src/proxy.ts`, and the `LANDING_PAGE` rows in `.env.example` and README.
3. **Landing page links to the app by origin.** `apps/landing-page/src/lib/links.ts` exports `APP_URL`:
   `process.env.APP_URL`, else `http://localhost:3030` in development, else a production constant
   (placeholder until the domain is picked, see Open questions). Set on the Vercel landing project, never in a local
   env file. `GITHUB_URL` and `ADELI_URL` move here too. "Sign in" / "Get started" go to `${APP_URL}/sign-in`.
4. **Shared package is source-only**, like `@adeli/ui`: `"exports"` point at `.ts`/`.tsx`/`.css` files, no build step.
   Each app's `globals.css` does `@source "../../../../packages/ui/src";` and imports `packages/ui/src/theme.css`.
   Add `transpilePackages: ["@adeli-chat/ui"]` only if the build needs it.
5. **What moves to `packages/ui`** (and nothing domain/server-side):
   - `src/app/globals.css` token block (light/dark, `@theme inline`, dark variant) becomes `src/theme.css`. Each app
     keeps a thin `globals.css` with its own base rules.
   - `src/components/ui/*` (all 21 shadcn components, so the app has one copy), `src/lib/utils.ts` (`cn`).
   - `src/components/brand/*` (`Wordmark`, `CursorLogo`), `src/components/theme-toggle.tsx`.
   - `PhonePreview` and the pure pieces it renders: the `AutomationContent` shape, `EmailCapture` / `emailCaptureOf`,
     `PREVIEW_FALLBACK_KEYWORD`, `PreviewTab`, `AdeliAccount` display fields. Split `src/lib/automations/schemas.ts`
     so the zod schemas stay in `apps/web` and keep `satisfies`/`z.infer` parity with the package's plain types
     (a type test in web asserts `z.infer<typeof automationContentSchema>` is assignable both ways). If that split gets
     ugly, fallback: move `schemas.ts` + `defaults.ts` (only depend on zod) into `packages/ui/src/automation/` whole.
   - `public/brand/*` is needed by both apps (`Wordmark` uses `next/image` with `/brand/...`): copy the files into
     each app's `public/brand/`, or inline the marks as SVG components in the package. Prefer inline SVG so there is
     one copy.
   - `components.json` (shadcn) goes into `packages/ui` with aliases pointing at the package, so `shadcn add` lands there.
6. **Imports.** Web code changes `@/components/ui/x` to `@adeli-chat/ui/components/x` (31 files) and `@/lib/utils`
   to `@adeli-chat/ui/lib/utils`. Do it with a codemod (`sed` over `apps/web/src`), then typecheck.
7. **Ignored build step** mirrors adeli: a shared `scripts/vercel-ignored-build-step.sh` at the root plus a wrapper per
   app listing its paths. Root files are the same as adeli's: `package.json yarn.lock .yarnrc.yml .yarn .nvmrc`. Drop the
   `beta` target and the `auto-deploy:` sentinel (neither exists here). Keep: skip non-production, prefer
   `VERCEL_GIT_PREVIOUS_SHA`, fall back to `HEAD^`, build whenever unsure.
   - `apps/web/scripts/vercel-ignored-build-step.sh`: `apps/web packages/ui`
   - `apps/landing-page/scripts/vercel-ignored-build-step.sh`: `apps/landing-page packages/ui`
   - Vercel setting on each project: Root Directory `apps/<name>`, Ignored Build Step `sh scripts/vercel-ignored-build-step.sh`.
   - Note for self-hosters in README: the script skips Preview builds; clear the setting if you want previews.

## Steps

Each step ends green (`yarn typecheck && yarn lint && yarn test && yarn build` from the root).

### 0. Switch to yarn (before any move)

- `corepack enable && yarn set version 4.12.0`, add `.yarnrc.yml` and the `.gitignore` lines from decision 1,
  `rm package-lock.json && yarn install`.
- `.nvmrc` with `24.22.1` (matches adeli and the local Node), `engines.node` to `>=24.22.1 <25`.
- Swap `npm run` for `yarn` in `package.json` scripts, README, `docs/local-development.md`, `.claude/launch.json`
  and CI (decision 1 and step 6). Still a single package here, so this commit is only the package-manager change
  and is easy to review on its own.

### 1. Move the app into `apps/web` (pure move, no behavior change)

- `git mv` into `apps/web/`: `src`, `test`, `drizzle`, `public`, `scripts/migrate.mjs` (to `apps/web/scripts/`),
  `next.config.ts`, `tsconfig.json`, `vitest.config.ts`, `drizzle.config.ts`, `components.json`, `eslint.config.mjs`,
  `postcss.config.mjs`, `.env.example`.
- `apps/web/package.json`: today's `package.json` renamed `@adeli-chat/web`, with all deps and scripts
  (`dev`, `build`, `vercel-build`, `start`, `lint`, `typecheck`, `test`, `db:generate`, `db:migrate`).
- Root `package.json`: `private`, `packageManager`, `workspaces`, `engines`, and scripts:
  `dev` / `dev:web` (`yarn workspace @adeli-chat/web dev`), `dev:landing`, and `build`, `lint`, `typecheck`, `test`
  (`yarn workspaces foreach -Apt --exclude adeli-chat run <script>`), `db:generate`, `db:migrate` (web).
- `yarn install` from the root to update `yarn.lock` for the new workspace; check no version drift beyond hoisting.
- Move `.env.local` to `apps/web/.env.local` in every checkout (the main checkout and this worktree). Next, drizzle
  config and `migrate.mjs` all resolve it from `apps/web` once scripts run there. PGlite's `./.data` becomes
  `apps/web/.data`; mention moving the old folder in `docs/local-development.md`.
- `.gitignore`: patterns are unanchored already, except `/.data/` becomes `.data/`. Keep `.env*` / `!.env.example`.
- `.claude/launch.json`: `yarn dev:web` (port 3030) and a second config for `dev:landing` (3031).
- `eslint.config.mjs`: ignore `.worktrees/**` stays at the web level; root needs no eslint config because lint runs
  per workspace.

### 2. Extract `packages/ui`

- Create `packages/ui` (`package.json` with `exports` map, `tsconfig.json`, `components.json`), move the files listed
  in decision 5, codemod web imports, update `apps/web/src/app/globals.css` to import `theme.css` and `@source` it.
- `PhonePreview` split per decision 5; keep its existing tests in web or move them with it (package gets a
  `vitest.config.ts` and a `test` script if tests move).
- Docs that say "Adeli's copied `components/ui`" (`CLAUDE.md`, `docs/brand.md`) now point at `packages/ui`.

### 3. Create `apps/landing-page`

- Next 16 app with the same Next/React/Tailwind/TypeScript versions as web, `dev` on port 3031, deps:
  `@adeli-chat/ui`, `next`, `react`, `react-dom`, `next-themes`, `lucide-react`, `react-icons`.
- Move from web: `src/components/landing/*` and `public/landing/*`. The page becomes `src/app/page.tsx` (static,
  no `force-dynamic`), carrying PR #11's `metadata`. Layout wraps `ThemeProvider` from `next-themes` like web's.
- `HeroPreview` imports `PhonePreview` and the sample content from `@adeli-chat/ui`.
- Add `robots.ts`, `sitemap.ts` and `icon.png` / `apple-icon.png` (copied from web's `src/app/`) so the site is
  complete on its own.
- No `.env.example` here; README explains `APP_URL` for the Vercel project.

### 4. Strip the landing page out of web

- `apps/web/src/app/page.tsx` back to `redirect("/automations")`; remove `landing.ts` and the proxy exceptions
  (decision 2). Keep the `PhonePreview` `disclaimer` prop and header fix from #11 (now in the package).
- `agent-connect.tsx` changes from #11 that reference landing code: re-point or keep as they are.

### 5. Ignored build step scripts

- Root `scripts/vercel-ignored-build-step.sh` (shared logic) and the two wrappers from decision 7, all `chmod +x`.
- Quick local check: `VERCEL_ENV=production sh apps/web/scripts/vercel-ignored-build-step.sh; echo $?` on a commit
  that only touches `apps/landing-page` should print "skipping" and exit 0, and exit 1 for one touching `packages/ui`.

### 6. CI and docs

- `.github/workflows/ci.yml`: `node-version-file: .nvmrc`, `corepack enable`, `yarn install --immutable`, with `cache: yarn` on setup-node, then the root `typecheck`, `lint`,
  `test`, `build` scripts (they fan out to every workspace).
- `README.md`: "Run it locally" (`corepack enable`, `yarn install`, `cp apps/web/.env.example apps/web/.env.local`, `yarn dev`), "Deploy to Vercel"
  (import with Root Directory `apps/web`; `vercel-build` still migrates then builds), and a short "Landing page"
  section (second Vercel project, Root Directory `apps/landing-page`, `APP_URL`). Drop `LANDING_PAGE`.
- `docs/local-development.md`, `CLAUDE.md` (paths: `apps/web/src/lib/...`, env file location, new layout),
  `docs/PRD.md` §10 if it lists file paths.
- PR #11 description: update "Code changes" and "To ship" (two Vercel projects, domains, Google OAuth redirect URI
  and `APP_URL` on the app subdomain).

## As built (2026-11-11)

Implemented on this branch, one commit per step (steps 3 and 4 together, since web does not build between them). Where it differs from the plan above:

- **Shared automation code:** `schemas.ts` and `defaults.ts` moved whole to `packages/ui/src/automation/` (the fallback in decision 5). Splitting the zod schemas from plain types would have duplicated every nested type. `PhonePreview` owns `PreviewTab` and takes `PreviewAccount` (`displayName`, `displayIdentifier`, `avatarUrl`), which `AdeliAccount` satisfies.
- **Logo:** `adeli-logo.png` is a PNG, so it is copied into each app's `public/brand/` rather than inlined as SVG.
- **Landing page env:** `APP_URL` (server-side, read at build; the page is static), not `NEXT_PUBLIC_APP_URL`. Unset, it links to `http://localhost:3030`, except in a Vercel production build, which fails. `robots.txt` and the sitemap use `VERCEL_PROJECT_PRODUCTION_URL`.
- **`transpilePackages`:** not needed; Next compiles the workspace package's TypeScript as is.
- **Ignored build step:** `VERCEL_TARGET_ENV=beta` and the `auto-deploy:` sentinel are dropped, as planned. Checked locally: previews skip; a commit touching only `apps/landing-page` builds the landing page and skips the app; one touching `packages/ui` builds both.
- **Web dependencies:** `@base-ui/react`, `class-variance-authority`, `clsx`, `cn` and `tailwind-merge` moved to `packages/ui` (`cn` was unused and dropped).
